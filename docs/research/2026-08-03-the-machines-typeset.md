# The machines, typeset

The corpus of small machines now describes itself. Every registered kind
carries a live-verified input contract; every machine has a transition
table; every table has a computed structural class, a five-tuple in
standard notation, and a state diagram. This document demonstrates each
claim with a command and its output. The pictures live in a companion
artifact, `docs/research/2026-08-03-automata-compendium.html`, which
typesets all of it — the tuples in Greek, the state maps with their
literature citations, the delta tables, the diagrams — and is
regenerated by three commands its footer records. Nothing below is
described from memory; every block was pasted from a run on 2026-08-03.

The registry and the contract set agree:

## One machine in full

`calculus/direct_substitution` entered the registry this evening. It
models the first limit strategy a student meets: substitute the target
into a polynomial and name the value as the limit. Its table, read
straight from the generated Prolog:

```console
$ swipl -q -g "consult('knowledge/strategies/transition_tables/calculus.pl'), \
    automaton_tuple(calculus, direct_substitution, S, A, St, Acc), \
    format('~w~n~w~n~w ~w~n',[S,A,St,Acc]), \
    forall(automaton_transition(calculus, direct_substitution, F, Act, T, P), \
    format('  ~w --~w--> ~w  [~w]~n',[F,Act,T,P])), halt."
states([q_start,q_step_1,q_step_2,q_step_3,q_step_4,q_step_5,q_accept])
actions([identify_limit_target,recognize_polynomial_is_continuous,substitute_target_into_polynomial,evaluate_polynomial_at_point,kernel_trace,name_value_as_limit])
start(q_start) accepting([q_accept])
  q_start --identify_limit_target--> q_step_1  [provenance(static(knowledge/strategies/math/calculus_limits_action_pairs.pl:96))]
  q_step_1 --recognize_polynomial_is_continuous--> q_step_2  [provenance(static(knowledge/strategies/math/calculus_limits_action_pairs.pl:96))]
  q_step_2 --substitute_target_into_polynomial--> q_step_3  [provenance(static(knowledge/strategies/math/calculus_limits_action_pairs.pl:96))]
  q_step_3 --evaluate_polynomial_at_point--> q_step_4  [provenance(static(knowledge/strategies/math/calculus_limits_action_pairs.pl:96))]
  q_step_4 --kernel_trace--> q_step_5  [provenance(static(knowledge/strategies/math/calculus_limits_action_pairs.pl:96))]
  q_step_5 --name_value_as_limit--> q_accept  [provenance(observed contract rows follow the same chain)]
```

The compendium renders this machine as M = (Q, Σ, δ, q₀, F): Q is the
seven states above written q₀ through q₆ with the ASCII atoms kept
beside them, Σ is the six-action alphabet, δ is the table, q₀ = q_start,
F = {q_accept}. Static rows record what the module's authored trace
declares; observed rows record what the machine actually did when its
contract example ran. The two provenances stay distinguishable in every
table and every diagram.

## What shapes the tables actually have

A transition table that never branches is the record of one accepting
run — a machine that accepts exactly one word. Calling such a table a
finite automaton is true and nearly empty, so the typology says what
each table witnesses and no more:

```console
$ swipl -q -g "consult('knowledge/strategies/machine_typology.pl'), \
    forall(member(C,[linear_trace,branching,looping,branching_looping]), \
    (aggregate_all(count, machine_structure(_,_,class(C),_,_,_,_,_), N), format('~w ~w~n',[C,N]))), \
    aggregate_all(count, machine_structure(_,_,_,_,_,_,_,_), T), format('total ~w~n',[T]), halt."
linear_trace 214
branching 7
looping 0
branching_looping 1
total 222
```

Two hundred fourteen tables record one run each. Seven branch. One —
`fraction/add_numerator_denominator_comparison` — both branches and
loops: its numerator-and-denominator adding state feeds itself once per
fraction before moving on. No table loops without branching. Four
machines carry class claims their modules document in prose — the
recursive place-value counter as a pushdown counter among them — and
those live in `knowledge/strategies/machine_class_attestations.pl`,
displayed apart from the computed classes, because a transition table
cannot witness a stack and the compendium does not pretend one can.

## When the wrong doing gets the right answer

`multiplication/add_instead_of_multiply` models a documented
misconception: treat the group count and the group size as addends. On
two groups of two it produces four, and four is the product. The
machine now says exactly that:

```console
$ printf '%s\n' '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"strategy_trace","arguments":{"strategy":"add_instead_of_multiply","input":{"a":2,"b":2}}}}' | python3 -m hermes.mcp.server --mode core | python3 -m json.tool
...
            "result": "4",
            "expected": "4",
            "validity": "accidentally_correct",
            "viability_context": "viability(accidental_success,validity(accidentally_correct))"
...
```

On two groups of three the same doing separates from the truth, and the
same machine says that instead:

```console
$ printf '%s\n' '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"strategy_trace","arguments":{"strategy":"add_instead_of_multiply","input":{"a":2,"b":3}}}}' | python3 -m hermes.mcp.server --mode core | python3 -m json.tool
...
            "result": "5",
            "expected": "6",
            "validity": "incorrect",
            "viability_context": "viability(fails_in_context,condition(additive_count_diverges_from_composite_unit_total),expected(6),produced(5),validity(incorrect))"
...
```

Sixteen deformations whose answers can coincide with the truth received
this treatment on 2026-08-03. Before it, each claimed
`validity(incorrect)` on every input, and every coinciding input was a
recorded purport violation — a machine calling itself wrong while being
right. The coincidence sweep now shows zero violations across all
sixteen. The rule that rides with the labels: a recognizer may charge
one of these misconceptions on an input only if the deformation
separates from the truth there. `deformation_separates_on/4` is that
test, per input, at runtime.

The mathematical object behind the coincidences is an equalizer, not a
fixed point: for a productive machine computing f and its deformation
computing g, the coinciding inputs are the set where f and g agree. For
adding instead of multiplying over the swept grid that set is a single
point:

```console
$ rg -n "add_instead_of_multiply" knowledge/strategies/deformation_coincidence.pl
99:coincidence_profile(multiplication, add_instead_of_multiply, deformation, ran(400), coincide(1), rate_pct(0), sample_coincide(some(2,2)), ...).
```

## Always right, never grounded

One deformation coincides with the truth on every swept input:

```console
$ rg -n "cross_multiplication_rule_without_ground coincides|coincidence_profile(fraction, cross_multiplication_rule_without_ground" knowledge/strategies/deformation_coincidence.pl
112:coincidence_profile(fraction, cross_multiplication_rule_without_ground, deformation, ran(1764), coincide(1764), rate_pct(100), purport_violations(0), sample_coincide(some(fraction_pair(1,2,1,2),unit(whole))), sample_separate(none), sample_violation(none)).
```

The multiply-across rule without ground gets every product right —
what it loses is the reason the rule works, not the answers. It keeps
`validity(correct)` for that reason, and no answer-based check can ever
distinguish it from the grounded rule. Only the trace can: the grounded
machine's steps construct the common unit; this machine's steps do not.
A student who holds it would pass every test and never once have
multiplied fractions with understanding. The corpus contains that
possibility as a measured fact, and the recognizer's only honest route
to it is reading steps, which is what the transition tables exist for.

## What a sentence gets

The recognizer searches observed transitions, and its corpus doubled
when the extractor learned the structured operands. An affirmed
make-ten description still lands cleanly:

```console
$ swipl -q -l paths.pl -g '..., recognize_strategies("i split the other number and made ten then i added the leftover and used both parts", Cs), ...'
make_ten_split_leftover 1.0000
make_ten_drop_leftover 0.1016
drop_regrouping_remainder 0.0571
regroup_to_base_preserving_total 0.0357
```

Under a denial the veto removes what the sentence denies and keeps the
clause after it — no make-ten candidate appears, and the counting
candidates survive:

```console
$ swipl -q -l paths.pl -g '..., recognize_strategies("i did not make ten i just counted them all", Cs), ...'
compare_solid_volume_by_cube_count 0.0200
mode_as_maximal_frequency 0.0167
area_model_part_of_part 0.0125
count_all_instead_of_known_fact 0.0125
count_all_when_count_on_available 0.0125
...
```

The list is honest about a cost. Counting words now reach counting
actions in geometry and statistics machines too, so the same sentence
supports more candidates, each more weakly. The admission floor became
corpus-relative when the fixed threshold silently emptied this very
sentence's candidates; the recognition benchmark recorded the trade —
no recall row regressed, the literature arm did not move, and
candidates per firing widened. Recognition from student words remains
the separate hard problem it was yesterday; the corpus doubling changed
what it can reach, not how hard it is.

## Why this is useful

A teacher's question about a student's step needs a machine that can
say what doing the step belongs to, whether that doing separates from
the truth on this problem, and what it would take to tell. The corpus
can now be read three ways at once — as runnable machines behind one
page, as typeset objects a reader versed in automata can inspect, and
as a ledger of exactly where its own claims stop. The compendium is the
middle reading: every machine with its tuple, its table, its shape
named honestly, and its picture.
